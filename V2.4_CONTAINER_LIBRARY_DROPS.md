# V2.4: Container Accepts Library Drops

## 🐛 Problem
Default container (and all multi-widgets) were not accepting drops from the widget library. Users couldn't drag Text, Button, or Image into containers.

## 🔍 Root Cause
Containers only accepted `DragTarget<PageWidget>` (moving existing widgets between containers), but the widget library drags `Map<String, dynamic>` (creating new widgets).

**Type mismatch**: Library drags `Map<String, dynamic>` → Container expects `PageWidget`

---

## ✅ Solution

### 1. Changed Container DragTarget to Accept Both Types

**Before**:
```dart
return DragTarget<PageWidget>( // Only accepts existing widgets
  onWillAccept: (draggedWidget) { ... },
  onAccept: (draggedWidget) {
    _handleNestedDrop(context, draggedWidget, widget);
  },
  ...
)
```

**After**:
```dart
return DragTarget<Object>( // Accepts both types (Object instead of dynamic for Flutter compliance)
  onWillAccept: (draggedData) {
    if (draggedData is Map<String, dynamic>) {
      return true; // Library widget
    }
    if (draggedData is PageWidget) {
      return WidgetTreeHelper.canDropInto(...); // Existing widget
    }
    return false;
  },
  onAccept: (draggedData) {
    if (draggedData is Map<String, dynamic>) {
      _handleLibraryDrop(context, draggedData, widget); // NEW
    } else if (draggedData is PageWidget) {
      _handleNestedDrop(context, draggedData, widget); // Existing
    }
  },
  ...
)
```

### 2. Added `_handleLibraryDrop` Method

New method to handle drops from widget library:

```dart
void _handleLibraryDrop(
  BuildContext context,
  Map<String, dynamic> widgetData,
  PageWidget targetContainer,
) {
  // Calculate vertical position (column layout)
  final existingChildren = WidgetTreeHelper.getChildren(...);
  
  double yPosition = 20.0; // Top padding
  if (existingChildren.isNotEmpty) {
    yPosition = maxBottom + 16.0; // 16px spacing
  }

  // Create new widget with parent reference
  final newWidget = PageWidget(
    id: const Uuid().v4(),
    type: widgetData['type'],
    position: Offset(20.0, yPosition), // Relative to container
    size: Size(
      widgetData['defaultWidth'] ?? 150,
      widgetData['defaultHeight'] ?? 60,
    ),
    properties: widgetData['properties'],
    parentId: targetContainer.id, // ✅ Set parent
  );

  // Add to page
  context.read<PageBloc>().add(AddWidgetToPage(newWidget)); // Correct event name
}
```

### 3. Fixed Compilation Errors

- Changed `DragTarget<dynamic>` → `DragTarget<Object>` (Flutter type requirement)
- Changed `AddPageWidget` → `AddWidgetToPage` (correct event name)

## 📐 How It Works

### Library Drop Flow

1. **User drags Text from library** → `Map<String, dynamic>` with type, width, height, properties
2. **Hovers over Container** → `onWillAccept` checks `is Map<String, dynamic>` → returns `true`
3. **Drops into Container** → `onAccept` calls `_handleLibraryDrop`
4. **Calculate position**: 
   - First child: `yPosition = 20.0`
   - Subsequent: `yPosition = maxBottom + 16.0`
5. **Create PageWidget** with:
   - New UUID
   - Type from library data
   - Relative position (20, yPosition)
   - Default size from library
   - Properties from library
   - **parentId = container.id** ✅
6. **Dispatch AddPageWidget event** → Adds to page
7. **Container re-renders** → Shows child inside

### Moving Existing Widget Flow

1. **User drags existing Text widget** → `PageWidget` object
2. **Hovers over Container** → `onWillAccept` checks `canDropInto` → returns `true`
3. **Drops into Container** → `onAccept` calls `_handleNestedDrop`
4. **Dispatch MoveWidgetToParent event** → Updates parent reference
5. **Container re-renders** → Shows child inside
