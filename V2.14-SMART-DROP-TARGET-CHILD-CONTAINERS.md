# V2.14: Smart Drop - Target Child Containers

## Summary
Reverted V2.13 changes to restore intelligent drop behavior. Now when you hover over a child container, the widget drops INTO the child (not the parent). This provides Figma-like precision for nested layouts.

## Problem with V2.13
V2.13 used `IgnorePointer` to allow dropping anywhere on containers, but this caused:
- ❌ Always dropped into parent container
- ❌ Couldn't target specific child containers
- ❌ Loss of nesting precision
- ❌ Unexpected behavior (hovering over child but dropping into parent)

## New Behavior (V2.14)

### How It Works Now:
Flutter's DragTarget has built-in "hit testing" that prioritizes the **deepest** (most nested) widget:

1. **Hover over child container** → Child's DragTarget receives event → Drops into child ✅
2. **Hover over empty area of parent** → Parent's DragTarget receives event → Drops into parent ✅
3. **Hover over non-container widget** → Parent's DragTarget receives event → Drops into parent ✅

This is the correct and expected behavior!

## How to Use

### Scenario 1: Adding to Nested Container
**Goal:** Add a Button into an inner Container

1. Drag Button from library
2. Hover over the inner Container (you'll see green border on it)
3. Drop
4. Button appears inside the inner Container ✅

### Scenario 2: Adding to Outer Container
**Goal:** Add another Container beside existing nested structure

1. Drag Container from library
2. Hover in empty area of outer Container (avoid hovering over children)
3. Green border appears on outer Container
4. Drop
5. New Container appears as sibling to inner Container ✅

### Scenario 3: Deep Nesting
**Goal:** Create Container > Card > Column structure

1. Start with Container on canvas
2. Drag Card, hover over Container, drop → Card inside Container
3. Drag Column, hover over Card (not Container!), drop → Column inside Card
4. Result: Container > Card > Column ✅

## Visual Feedback Guide

### Green Border Indicator:
The green border always shows which container will receive the drop:

- **Green on Child**: Will drop into child
- **Green on Parent**: Will drop into parent
- **No Green**: Cannot drop here (not a container)

### Drop Zone Label:

## Changes Made

### Frontend Changes

#### `frontend/lib/features/page/views/page_canvas_view.dart`

**Reverted V2.13 changes:**
- Removed `IgnorePointer(ignoring: isHovering)` from children
- Restored default Flutter hit testing behavior
- DragTargets now properly nested with correct precedence

**Code:**
```dart
child: Stack(
  children: [
    // Children can now receive drag events (NOT ignored)
    _buildWidgetContent(
      widget,
      false,
      isSelected,
      children,
      allWidgets,
    ),
    
    // Visual indicator for drop target
    if (isHovering)
      Positioned.fill(
        child: IgnorePointer(  // Only the indicator ignores pointer
          child: Container(/* Green overlay */),
        ),
      ),
  ],
),
```

## Technical Details

### Flutter's Hit Testing:
- Works from front (top layer) to back (bottom layer)
- Child widgets are rendered "on top" of parents
- First widget to accept the drag gets the event
- Parents only receive events if children don't accept

### DragTarget Hierarchy:
```
DragTarget (Parent Container)
  └─ Child Widgets
       └─ DragTarget (Child Container)
            └─ More Child Widgets
```

When dragging over child container:
1. Event hits child DragTarget first
2. Child accepts → Parent never sees event
3. Drop happens in child

When dragging over empty area:
1. Event doesn't hit any child
2. Parent DragTarget receives event
3. Drop happens in parent
